# 낑기타자 프로덕션 리디자인 설계

작성일: 2026-09-08  
상태: 사용자 승인 완료

## 목표

부산대역의 고정 승차 지점에서 부산대학교의 관리형 고정 하차 지점으로 이동하는 익명 사용자를, 예측 가능하고 안전한 서버 권위 매칭으로 최대 4명까지 연결한다. 기존 Next.js 16과 Supabase 기반은 유지하되 매칭 상태 머신, 전체 사용자 여정, 관리자 운영 화면, 디자인 시스템을 하나의 계약으로 재구성한다.

프로덕션 직전의 완료 기준은 코드, additive 데이터베이스 마이그레이션, 운영 문서, 빌드, 테스트와 로컬 실사용 QA가 완료된 상태다. 실제 Supabase 프로젝트 적용과 외부 배포는 포함하지 않는다.

## 확정된 제품 정책

- 하차 지점은 관리자가 추가, 수정, 정렬, 비활성화하는 고정 지점이다.
- 매칭 풀의 키는 `pickup_spot_id + drop_zone_id`이다.
- 일행은 1~3명이며 분할하지 않는다.
- 공유 매칭은 서로 다른 대기 엔트리 2개 이상, 총 2~4명일 때만 성립한다.
- `fast`와 `cheap`은 같은 풀을 공유한다.
- 4명이 되는 조합은 선호와 무관하게 즉시 제안한다.
- 총 2~3명은 구성원 전원이 `fast`일 때만 제한시간 전에 제안한다.
- `cheap`이 포함된 부분 조합은 서버 기준 최대 3분 대기 후 제안한다.
- 대기와 집합 제한시간은 각각 3분이다.
- 매칭 제안은 서버 기준 20초이며 모든 엔트리가 수락해야 팀이 확정된다.
- 거절 또는 미응답으로 제안이 해산되면 피해 사용자의 기존 대기 우선순위를 보존한다.
- 모든 시간 판정과 상태 전이는 서버가 담당한다. 클라이언트 타이머는 표시용이다.

## 상태 모델

```text
queued -> offered -> assembling -> ready -> departed -> completed
queued -> cancelled | expired
offered -> paused | queued
assembling -> cancelled | no_show
any UI -> recoverable_error | not_found | no_session
```

매칭 후보 선점, 제안 생성, 멤버 기록은 단일 PostgreSQL 트랜잭션에서 성공하거나 모두 실패한다. 비원자적 fallback은 사용하지 않는다. 팀 번호는 KST 서비스 날짜별로 원자적으로 채번한다.

집합 마감 전에는 모든 활성 엔트리가 도착한 경우에만 출발 준비 상태가 된다. 마감 후 도착한 엔트리가 두 개 이상이면 노쇼를 제외하고 출발할 수 있다. 한 엔트리만 남으면 공유 매칭은 취소한다. 출발은 준비 완료 상태에서만 멱등적으로 처리한다.

## 사용자 여정

### 조건 선택

한 화면에서 승차 지점, 하차 지점, 일행 수, 매칭 선호를 선택한다. 활성 하차 지점 카탈로그는 실시간 대기 현황 API 실패와 무관하게 항상 표시한다. 하차 카드에는 도보 시간, 대기 좌석, 조건부 예상 요금을 표시한다. CTA는 선택 결과를 포함한다.

### 대기

현재 좌석, 내 일행 좌석, 서버 기준 남은 시간, 실제 매칭 규칙, 연결 상태, 마지막 동기화 시각을 보여준다. 탭 visibility 또는 heartbeat만으로 약속된 대기시간보다 일찍 만료하지 않는다. 새로고침과 재접속 시 익명 세션으로 현재 상태를 복원한다.

### 매칭 제안

접근 가능한 전체화면 dialog에서 총 인원, 승차 지점, 하차 지점과 20초 제한시간을 보여준다. 전원 수락 후에만 팀을 확정한다. 미응답 사용자는 반복 제안을 막기 위해 일시정지하고 직접 재개하도록 한다.

### 팀 집합과 출발

큰 팀 번호, 승차 랜드마크, 집합 마감, 엔트리별 일행 수와 도착 상태, 본인 도착 CTA 순으로 구성한다. 서버 성공 응답 전에는 성공 UI를 표시하지 않는다. 마감 후 제외 출발은 노쇼 대상과 결과를 명시하는 확인 절차를 거친다.

### 정산과 결과

대표가 실제 총 택시비와 정산 계좌를 등록하면 실제 탑승 인원 기준으로 1인 및 일행별 예상 부담액을 계산한다. 외부 송금 연동과 송금 완료 추적은 범위에서 제외한다. 결과 화면은 완료, 만료, 취소, 팀 해산, 세션 없음, 잘못된 링크, 네트워크 오류를 각각 종결 가능한 상태로 제공한다.

## 관리자

하차 지점은 변경 불가능한 ID, 이름, 설명, 권역, 도보 시간, 노출 순서, `draft | active | inactive` 상태를 가진다. 삭제 대신 비활성화한다. 활성 승차 지점별 유효 요금이 없으면 활성화할 수 없다. 비활성화는 신규 접수만 막고 기존 흐름은 완료시킨다. 모든 변경은 인증된 서버 API를 통하며 브라우저에서 service-role 데이터 변경을 직접 수행하지 않는다.

운영 화면은 현재 대기 좌석, 가장 오래 기다린 시간, 오늘 매칭 수, 충원율, 제안 수락률, 집합 성공률, 노쇼율과 API 오류 상태를 우선한다.

## 데이터와 요금

기존 네 하차 지점 ID는 유지한다. 카탈로그 활성 상태와 순서, 대기 우선순위와 서버 마감, 정책 버전, 매치 멤버 이력, 제안 상태, 서비스 날짜, 요금과 경로 스냅샷을 additive migration으로 추가한다.

요금이 없으면 임의 범위를 반환하지 않고 해당 경로 접수를 막는다. 매치 생성 당시 총 택시요금 범위를 스냅샷하고, 실제 활성 탑승 인원을 기준으로 개인 및 일행 예상 부담액을 계산한다. 화면에는 실제 미터 요금 기준 정산이라는 점을 명시한다.

## 디자인 시스템과 접근성

- public shell과 admin shell을 분리한다.
- 신뢰감 있는 blue/neutral 팔레트와 성공, 주의, 오류 semantic token을 사용한다.
- 4px spacing 체계, 48px 이상 touch target, 공용 radius, shadow, focus ring을 정의한다.
- 선택 UI, dialog, toast, loading, error state에 올바른 HTML/ARIA 의미 구조를 제공한다.
- 상태 전달을 emoji나 색상에만 의존하지 않는다.
- `prefers-reduced-motion`을 지원한다.
- 320, 375, 768, 1280px에서 가로 스크롤이나 가려진 CTA가 없어야 한다.
- WCAG 2.2 AA를 목표로 한다.

## 검증 기준

- 모든 매칭은 서로 다른 엔트리 2개 이상이며 총 인원은 4명을 넘지 않는다.
- 한 세션에는 활성 대기 엔트리가 하나뿐이다.
- 동시 트리거에서도 엔트리가 두 매치에 속하지 않는다.
- `1+1 fast`, `1+1 cheap timeout`, `3+1`, `3+2 충돌`, 제안 거절과 미응답, 숨김 탭 복귀, 노쇼 제외 출발을 검증한다.
- 실시간 대기 조회 실패 시에도 카탈로그와 선택값은 유지된다.
- 모든 비동기 화면은 성공, 명시적 빈 상태 또는 재시도 가능한 오류로 끝난다.
- 서버가 2xx를 반환하기 전에 UI가 성공을 표시하지 않는다.
- 키보드만으로 핵심 사용자 여정을 완료할 수 있다.
- Next.js production build, TypeScript, lint, 핵심 테스트가 통과한다.
- 프로덕션과 동일한 로컬 실행에서 모바일과 데스크톱 사용자 여정을 수동 검증한다.
